# Quality decisions · 2026-11-03

## Scope and acceptance

Keep the local-first React / TypeScript / Vite / IndexedDB architecture. Merge `origin/main` at `589d202` into the implementation (`f959d19`); retain existing implementation and README documentation. The working tree was clean before merging; no local edits were discarded. No push or deployment is part of this change.

The core demonstration is **winner → written reason → explicitly linked source-time observations (including rejected candidates) → generation record → portable ZIP → restored project**. IDs must survive the round trip. A winner without a reason or linked evidence is visibly incomplete. Changing the winner must not transfer the old rationale. Missing or moved evidence must not silently point elsewhere. Unknown generation details remain unknown.

This is a workflow hypothesis, not a novelty or speed claim. The functional advantage over a folder + ordinary player + notes is an explicit, machine-readable relationship instead of manual filename/time/prompt cross-referencing. Whether creators will maintain those records, make better choices, or finish faster remains untested with users.

## Design direction retained

Compared a professional review desk (stable preview positions, dense source metadata, shared transport) with a lighter visual material board (large thumbnails and browsing emphasis). Retain the review desk because the acceptance task depends on watching the same moment and identifying the source of evidence. A board would use more space and weaken time relationships; no major redesign is warranted.

Graphite surfaces and neutral footage surrounds; blue for focus/actions, green only for selection, amber/red for observation states with text/icons. System typography with tabular time digits; 4/8/12/16 px spacing rhythm. Extend the existing inspector with a compact “Decision / 选片依据” tab, named source, rationale, checkable observations and source-time jump controls. Do not crop differently sized clips to fill cards. Hide the decision record during blind review because manually written reasons may mention a model. Refer to “source time” and “review offset” explicitly rather than implying a source-frame number.

Check keyboard focus, readable contrast, 390 px layout, 200% equivalent narrow layout, English/Chinese, and reduced motion. These checks are not a WCAG 2.2 conformance audit. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) is the baseline.

## Synchronization protocol (set before measurement)

Use deterministic 1920×1080 H.264 fixtures: 24 fps / 8 seconds with audio; 30 fps / 5 seconds with audio. Exercise one and two decoders, a 0.5-second offset, play/pause, settled seek, nominal stepping, 0.5× / 1× / 2×, loop, shorter source ending and audio selection. Nine-way procedural 360p demo remains a separate regression, not a 9×1080p performance claim.

After startup/seek settles, sample every 50 ms. Report media-clock spread and the latest `requestVideoFrameCallback` media timestamps adjusted by source offsets; exclude ended clips from pairwise spread and record their held frame separately. Callback timestamps are a browser-visible proxy for presentation, not an external screen/camera measurement.

Acceptance targets: steady presented timestamp spread p95 ≤ 80 ms and maximum ≤ 150 ms at 1×; after a seek all media clocks within 1/24 s of requested source time and settle within 750 ms; mixed-FPS presented-frame difference after a paused seek ≤ 1/24 s. Shorter clips hold their final frame, longer clips continue. No unintended simultaneous audio; loop reacquires alignment within 750 ms. Record decoded/dropped frame deltas and JS heap where available, with the explicit limit that JS heap excludes native decoder/GPU memory. At 2× allow a two-frame presented difference (≤ 84 ms p95) and report actual results.

Measure on this host and identify hardware/browser. It is not an ordinary-laptop certification. No speed, power or memory claim may be extrapolated to untested machines, mobile browsers, HEVC, VFR, 4K or nine 1080p streams. Results and reproducible commands belong in VALIDATION.md.

## Findings and implementation follow-through

The baseline hit 233.3 ms p95 / 258.3 ms maximum presented timestamp difference at 2×, with repeated decoder work. Replacing the independent wall-clock advance with the longest available source's actual media clock removed that failure in the same fixture. Keep the native pipeline; a WebCodecs rewrite is still disproportionate to this measured issue. Pause is immediate, redundant seeks are avoided, and normal interrupted-play AbortErrors are ignored.

A later run measured 83.3 ms p95 at 1× against the predeclared 80 ms target; media clocks differed by under 1 ms, while frame callbacks could be about 101 ms old. **The 80 ms target is not consistently met.** Retain the failed run, distinguish native clock alignment from visible/compositor callback timing, and do not claim frame lock. The benchmark receipt records target pass/fail separately; automated regression guards require clock p95 ≤ 100 ms, presented maximum ≤ 150 ms, settled seek ≤ 750 ms and valid pause/audio/end/loop behavior. A green functional run therefore does not certify the stricter p95 target. Original thresholds above remain the quality goal.

Visual inspection found that the previous rejected-state CSS reduced video opacity. Remove that transform: a verdict must not alter perceived brightness. Two visible candidates now occupy equal full-width columns instead of leaving an unused third column. The inspector's new decision tab extends the existing layout; no new navigation layer or dependencies.

## Continuation: strict gate and static-host portability

Added `npm run test:sync` to enforce the original p95 thresholds across three trials; ordinary regression runs annotate misses. Per-player frame/clock/expected-display metadata now supports diagnosis without assuming callback delay is playback drift. Six bounded trials did not justify further controller changes; the earlier miss remains documented.

A clean dependency installation and real static production host exposed bundled-demo seeking resetting to zero when the server returned whole HTTP 200 files without byte-range support. Fetching the small bundled sources into Blob URLs reuses the already-working imported-media path, with URL cleanup and a 15-second fetch timeout. This adds transient demo bytes, no dependency or decoder rewrite. The same production host then passed seeking, restore and export. See [follow-up receipts and limits](RELEASE_CHECK_2026-11-03.md).

## Interface revision after visual feedback

The earlier graphite direction is superseded by a lighter tool surface and neutral viewing area. Ray explicitly rejected the overall template-like appearance. Actual visual review covered Paper, Play and Feather (verified Apple Design Awards 2025 winners), ChatGPT's shell, and Claude/Gemini public sites. The comparison rationale also uses Gleicher's established research and his 2025 commentary, with access limitations stated. See [the reference analysis, alternatives and visual rules](UI_REDESIGN_2026-11-03.md).

The change removes repeated headings/statistics, enlarges previews, makes records collapsible and retains the local workflow. An existing between-update pause regression failed once during this revision: the media position and displayed nominal frame differed. Pause now freezes the leader's actual media clock, aligns the players and publishes the final readout, including the non-playing effect path. This fixes a concrete observation rather than justifying a decoder rewrite.
