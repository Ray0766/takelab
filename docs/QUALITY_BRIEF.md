# TakeLab — 研究、设计与验收 brief

本文件把项目质量要求具体化；配合根目录 [AGENTS.md](../AGENTS.md) 使用。初次资料核对：2026-11-03。项目仍处于规划阶段。

## 要解决的任务与核心亮点

创作者已经有多条生成视频，需要快速判断哪一条值得进入剪辑，并保留选择依据。建议优先验证“可追溯的选片工作台”：选择、时间点标记、人工理由与生成记录绑定，最终能导出供自己或协作者复核的选片包。这是差异化假设，不是已经验证的市场结论或论文创新。

首版流程：导入本地视频 → 按镜头分组 → A/B 同步比较或盲选 → 标记问题/选择版本 → 导出清单与素材引用。模型 API、自动打分、团队云协作均不应阻塞此闭环。

## 技术探索应回答什么

1. 用视频元素＋统一播放时钟作为基线，评估 WebCodecs、解码 worker、代理视频及缓存是否有实际收益；容器解析、编解码支持、可变帧率和硬件差异需分别处理。规范存在不代表目标浏览器支持所有 codec。
2. 若研究多模态模型辅助标注，先定义具体任务，如定位穿帮时间段或提示人物一致性问题。对照人工标注，记录误报/漏报、费用和时延；模型判断必须可忽略，不得强制决定“最佳”。
3. 元数据先支持手工编辑/sidecar；缺失提示词、seed 或成本时标为未知，不从视频内容猜成事实。记录来源、单位和适用的素材版本。
4. 任何自动质量分数都要保留维度、方法、版本及局限；不要把模型排行榜直接当作用户某个镜头的选择依据。

## 产品与视觉方向

- 工作区以画面为主，素材条、时间轴和标记服务选片；信息密度来自镜头任务，避免用通用数据看板作为首页。
- 建议比较“专业审片台”和“轻量视觉素材桌”两个方向，用同一组素材测试，选择操作路径更清晰的方案。深浅主题依据观看环境决定，不靠电影感滤镜制造特色。
- 比较时统一预览面积与缩放策略；明确不同长宽比、长度、时间偏移和实际帧率，不能静默裁切或插帧造成不公平对照。
- 盲选界面隐藏模型名、文件名及其他可辨来源；保留匿名 take ID，提交选择后再揭示身份。
- 文案使用“选中此版本”“标记问题时间点”等动作；机器观察、人工意见与原始生成记录有明确视觉区分。

## 首版验收与演示

| 检查 | 最小证据 |
| --- | --- |
| 核心闭环 | 用可分发样例完成导入、分组、比较、标记、保存、重新打开及导出；导出能追溯 take 与标记。 |
| 时间与音频 | 相同/混合帧率、不同片长及无音轨样例；记录 seek、循环、暂停后的对齐误差，音频只播放明确选中的来源。 |
| 负载 | 在声明的普通目标机器上测单路与双路 1080p，再按范围增加并发；记录丢帧、内存和响应时间，提前设定通过阈值与降级策略。 |
| 异常 | 损坏文件、缺失素材、重复导入、导出取消后仍可恢复，不改坏原文件。 |
| 使用价值 | 与逐个打开播放器的同一任务对照，记录切换步骤及完成时间；无真实用户样本时只称流程验证。 |

发布演示突出一次完整决策：两条候选 → 时间点证据 → 选片结果与生成记录。样例应包含画面好看但存在实际缺陷的反例，不只展示成功素材。
